$1.0$核心结论导读：为什么看离线指标容易混淆？

原实验呈现的表面现象并不能说明“生成 CoT 对动作选择没有益处”。 在 cot_action_diag 已跑完的 $120$ 局（$3{,}299$ 步）数据中，桥梁指标 $I_t$ 中位数接近 $0$（ScienceWorld 为 $0.0046$，TextWorldExpress 为 $0.0268$）、与单步奖励负相关（$\rho = -0.217$ 与 $-0.268$）、约 $80\%$ 的步落入 $(\hat{A}_t < 0,\, I_t > 0)$ 象限、且 Pass 4 自蒸馏差距 $D_{\mathrm{self}}$ 在约 $98\%$ 的步上为负。

之所以看这些数字容易发晕，根本原因在于把三个完全不同的实验问题混在了一起：$(1)$ 生成 CoT 能否提高整局做题成功率？（需跑在线对照）；$(2)$ 站在同一第 $k$ 步状态上，隐去 CoT 会不会让模型改选别的动作 $a_k'$？（需跑单步重解码或分叉采样）；$(3)$ 锁死已经选出的原动作 $a_k$ 不变，删掉当前 CoT 会让这个固定动作的对数概率掉多少？（原实验 02_score_offline.py 实际做的事）。理清这三件事的边界以及 vLLM 与 HF Transformers 的工程分工，所有反常数字都能得到精确解释。

$1.1$三类完全不同的实验问题与评估范式

在多轮交互环境（ReAct 轨迹：$o_0 \to z_0, a_0 \to o_1 \to \dots \to o_k \to z_k, a_k$）中，“评估 CoT 的作用”对应三种截然不同的操作协议。下方的流程示意图与表 $1.1$ 逐一给出它们的输入、动作采样方式与适用边界。

范式 A · 整局有/无 CoT 在线对照（Episode-Level Rollout，$120$ 题全流程对比）

执行引擎：vLLM + 环境并发交互 直接回答：生成 CoT 能否提升任务总成功率？

固定完全相同的 $120$ 个任务种子，分别独立运行完整轨迹。两组一旦在某一步选了不同动作，后续到达的房间和观察 $o_{t+1}'$ 也会自然分叉，最终直接比较终局通关率与总得分。

有 CoT 组：相同种子 $s$，初始观察 $o_0$
vLLM 自回归生成 $z_t \to a_t$
环境步进 $o_{t+1} \sim \mathcal{T}(s_t, a_t)$（循环至终局 $T$）
统计终局成功率 $\mathbb{E}[S_{\mathrm{succ}}^{\mathrm{cot}}]$
无 CoT 组：相同种子 $s$，初始观察 $o_0$
vLLM 直接生成纯动作 $a_t'$（或中性句 $+ a_t'$）
进入各自的真实环境分支 $o_{t+1}'$（循环至终局 $T'$）
对比差值 $\Delta S_{\mathrm{succ}} = \mathbb{E}[S^{\mathrm{cot}}] - \mathbb{E}[S^{\mathrm{no\text{-}cot}}]$

范式 B · 第 $k$ 步单步反事实干预（Turn $k$ Counterfactual Intervention）

直接回应“从第 $k$ 步切入重测”的设计方案 执行引擎：vLLM 批量采样

严格对齐前 $k-1$ 步走出的环境状态 $s_k$（消除轨迹漂移混杂），在第 $k$ 步隐去或中性化当前 CoT，让模型自由重采样新动作 $a_k'$。包含“往后怎么走（B1 vs. B2）”与“前 $k-1$ 步历史 CoT 怎么处理（保留 vs. 遮蔽）”两个正交维度：

B1 · 单步重解码（推荐，极快）：固定第 $k$ 步状态与前缀
隐去第 $k$ 步 CoT，vLLM 重采样新动作 $a_k' \sim \pi(\cdot\mid \tilde{h}_k, \varnothing)$
不重跑后续整局！直接对比 $a_k'$ vs. $a_k$ 的改变率、合法率 $\Delta v_k$ 与单步进度差（全量 $3{,}299$ 步仅需 $1\text{–}3$ 分钟）
B2 · 分叉重跑整局（昂贵）：在第 $k$ 步采出 $a_k'$
克隆环境状态并继续交互跑完 $k+1 \dots T$（每步分叉 $M$ 条）
得到精确长程价值差 $\hat{Q}(s_k, a_k) - \hat{Q}(s_k, a_k')$，但全量跑需约 $6.6\times 10^4$ 步（仅适合关键步抽样）

口径 $\text{B}_{\mathrm{keep}}$：保留前 $0\dots k-1$ 步历史 Thought:

输入 $(h_k^{\mathrm{full}}, \varnothing)$。测的是第 $k$ 步单步思考的边际增量效应（Marginal Effect）。若第 $0$ 步或第 $k-1$ 步的 Thought: 已经写明下一步计划（实测 SW 有 $12.4\%$ 的步直接提前写出后续动作），模型读历史思考即可选出同动作。

口径 $\text{B}_{\mathrm{mask}}$：将前 $0\dots k-1$ 步历史 Thought: 换成两行中性句

输入 $(h_k^{\mathrm{neu}}, \varnothing)$。测的是截至第 $k$ 步整条思维链的累积效应（Cumulative Effect）。既剥离了历史思考跨步泄漏，又保留了 Thought:\nAction: 两行输出模板，避免单行 Action: 引发格式突变。

范式 C · 固定轨迹离线 Teacher-Forcing 打分（原实验 02_score_offline.py Pass 1–4）

原动作 $a_k$ 被锁死，不重采样新动作 执行引擎：HF Transformers 单次前向

完全不与环境交互，也不让模型重选动作，而是把原轨迹已生成的动作 token 序列 $a_k$ 原封不动拼在三种前缀后面，计算同一个动作 $a_k$ 的对数似然变化：

已落盘样本 $(h_k, z_k, a_k)$
锁死 $a_k$ 的 token IDs 不变！分别拼接 $(h_k, z_k, a_k)$ 与 $(h_k, \varnothing, a_k)$
HF 单次前向算出 $I_k = \frac{1}{|a_k|}[\log\pi(a_k\mid h_k,z_k) - \log\pi(a_k\mid h_k,\varnothing)]$ 及精确熵 $H^C, H^A$

为什么单靠范式 C 测不出“CoT 好不好”，但它在 RL 训练里仍然有用？ 因为 $I_k$ 只回答“这段 CoT 把原动作 $a_k$ 的概率推高了多少”：若模型在 Thought: 里先误写了一条非法指令再原样照抄到 Action:，删掉 Thought: 后模型本来不会选该非法指令，此时 $I_k$ 反而很大（正值）；反之若目标就在眼前，无 CoT 概率已近 $100\%$，再好的推理也只能测出 $I_k \approx 0$。但在 RL 训练内部，一旦外层通过同种子多轨迹采样拿到了真实动作好坏优势 $A_k^{\mathrm{act}}$，$I_k$ 就能作为低成本门控权重 $g(I_k) \in [0,1]$，用来判定“该动作的功过有多少应归因于当步 CoT”。

$1.2$为什么代码要分成 vLLM 与 HF Transformers 两套引擎？

不少同学在看仓库时会疑惑：既然模型都是同一个本地 Qwen3-8B（bfloat16），为什么 01_run_rollout.py 用 vLLM，而 02_score_offline.py 又切回 HF Transformers？两者并不是重复造轮子，而是针对“自回归逐词生成”与“已知完整序列算全词表精确分布”两种完全不同的底层计算形态做的分工：

vLLM 负责：在线交互采样与第 $k$ 步重解码 范式 A / B1 / B2

  • 计算形态（Memory-Bound 循环解码）：模型不知道自己接下来会写出哪几个词，必须生成第 $1$ 个 token $\to$ 拼回输入 $\to$ 生成第 $2$ 个 token，生成完 Action: 还要暂停等待 Java 环境（ScienceWorld / TextWorldExpress）执行并返回下一步观察文本。
  • 核心加速机制：开启 enable_prefix_caching: true 与 $60$ 个并发环境槽位后，同一局相邻轮次之间约 $95\%$ 的历史对话 KV Cache 直接命中复用，Continuous Batching 动态合并不同进度的环境请求。
  • A800 实测速度：ScienceWorld $60$ 局（$1{,}924$ 步）仅耗时 $3\text{ 分 }52\text{ 秒}$；TextWorldExpress $60$ 局（$1{,}375$ 步）仅耗时 $57\text{ 秒}$。若改用 HF model.generate() 逐条跑，耗时将拉长约 $10$ 倍。
  • 为什么不直接拿它做 Pass 1–4 全词表熵？ vLLM 的生成采样接口默认只截取并返回概率最高的 $K$ 个（通常上限 $20$）候选词的 logprob，不直接暴露任意反事实拼接序列在完整词表（$|\mathcal{V}| = 151{,}936$）上的未截断 FP32 logits。

HF Transformers 负责：固定序列 Pass 1–4 对数似然与精确香农熵 范式 C

  • 计算形态（Compute-Bound 单次并行前向）：在 02_score_offline.py 中，整条序列 prompt_ids + cot_ids + action_ids 的每一个 token ID 都已确定，无需循环生成，调一次 decoder(input_ids) 即可在单次前向传播中同时算出所有位置的隐状态。
  • 全词表 $151{,}936$ 维精确熵与显存裁剪：若对整条 $4{,}000$ token 序列全量算 lm_head，[B, L, 151936] 张量在 bs=4 时会占约 $15\text{ GB}$ 显存。02_score_offline.py（第 $98\text{–}129$ 行）先只跑 model.get_decoder()，仅切出目标 CoT / Action 对应的几十个位置过 lm_head 并转 float32，无截断精确计算： $$H_{t,i} = -\sum_{v=1}^{151{,}936} \pi(v \mid h_t, z_{t,<i}) \log \pi(v \mid h_t, z_{t,<i})$$ 将峰值显存开销降低了约 $60$ 倍。
  • 共享前缀 KV 裁剪：Pass 1（原 CoT）、Pass 2（空 CoT）、Pass 3（中性 CoT）共享完全相同的 prompt_token_ids，代码先编码一次前缀并用 cache.crop(p_len) 反复回滚后缀，省去约 $2/3$ 重复计算（全量 $3{,}299$ 步四趟总计耗时 $23.2\text{ 分钟}$）。
对比维度 vLLM（01_run_rollout.py 及新增 02b_redecode_turn_k.py） HF Transformers（02_score_offline.py）
输入序列状态 仅给定截止当前步的提示前缀 prompt_token_ids，后续 token 未知 前缀 + 目标 CoT + 目标 Action 的完整 token IDs 全部固定已知

$2.1$问题一：$I_t \approx -\frac{1}{|a_t|}\log\pi(a_t \mid h_t, \varnothing)$ 恒等退化与状态显见度混杂

离线打分脚本定义的桥梁指标为两项长度归一化对数概率之差：

$$I_t = \underbrace{\frac{1}{|a_t|}\log \pi(a_t \mid h_t, z_t)}_{\text{Pass 1：含当前 CoT（均值 }-0.0085\text{ / }-0.0176\text{）}} - \underbrace{\frac{1}{|a_t|}\log \pi(a_t \mid h_t, \varnothing)}_{\text{Pass 2：空 CoT（均值 }-0.8480\text{ / }-1.3076\text{）}}$$

实测表明，一旦模型写完 Thought:，后续 Action: 几乎已成定局（SW 有 $95.2\%$ 的步单 token 平均动作概率 $>95\%$，中位数对数概率严格为 $0.0000$；TWX 有 $92.8\%$ 的步 $>95\%$）。第一项方差几乎为 $0$，导致 $I_t$ 超过 $99.9\%$ 的方差直接由第二项无 CoT 基础动作惊讶度 $-\frac{1}{|a_t|}\log\pi(a_t \mid h_t, \varnothing)$ 决定（SW Pearson $r = 0.9998, R^2 = 0.9996$；TWX Pearson $r = 0.9995, R^2 = 0.9991$）。

这一恒等关系立刻解释了为什么全局会出现 $\mathrm{Corr}(I_t, r_t) < 0$：由于 $\log\pi(a_t \mid h_t, z_t) \le 0$，数学上恒有上界 $I_t \le -\frac{1}{|a_t|}\log\pi(a_t \mid h_t, \varnothing)$。而在两个环境中，单步正奖励（$r_t > 0$，仅占 SW 的 $7.8\%$、TWX 的 $5.2\%$）高度集中在目标已出现在眼前、无需思考即可确定动作的收尾步（如 TWX 的 $71$ 个拿分步中有 $66$ 步为直接 take 或 put，占 $93.0\%$）：

  • 在 $r_t > 0$ 的显见拿分步上，无 CoT 基础惊讶度中位数在两边均为 $0.0000$（TWX 均值仅 $0.0568$，SW 均值 $0.3554$），因此 $I_t$ 被概率天花板严格截断在 $0$；

$2.5$问题五：短窗口 $\hat{A}_t$ 误伤成功轨迹铺垫步，且 Pass 4 单行历史触发上下文格式突变

最后两项反常现象——“约 $80\%$ 的步落在 $C_t = \hat{A}_t I_t < 0$ 象限”与“$98\%$ 的步 $D_{\mathrm{self}} < 0$”——完全源于两个代理指标本身的构造偏置：

（$1$）为什么成功通关局里也有高达 $61.5\%$ 的步被判为负优势 $\hat{A}_t < 0$？

02_score_offline.py 将优势代理定义为含当前步的 $3$ 步窗口累积奖励在任务内的标准化值：$\hat{A}_t = (\tilde{G}_t^{(3)} - \mu_{\mathrm{task}}) / (\sigma_{\mathrm{task}} + 10^{-6})$，其中 $\tilde{G}_t^{(3)} = r_t + r_{t+1} + r_{t+2}$。在稀疏奖励环境中，单步 $r_t = 0$ 占比达 $92.00\%$（SW）与 $94.84\%$（TWX），即使看 $3$ 步窗口，$\tilde{G}_t^{(3)} = 0$ 的步仍占 $82.33\%$（SW）与 $86.62\%$（TWX）（在 TWX coin 中高达 $95.5\%$）。只要任务内有少数拿分步使任务均值 $\mu_{\mathrm{task}} > 0$，所有距离终点超过 $3$ 步的必要开门、寻路、排查动作就会被自动扣上负优势 $\hat{A}_t < 0$。

实测即便只看最终成功通关的轨迹（terminal_success == True），SW 成功局的 $153$ 步中仍有 $39.22\%$（$60$ 步） 被判为 $\hat{A}_t < 0$；TWX 成功局的 $332$ 步中更有 $61.45\%$（$204$ 步） 被判为 $\hat{A}_t < 0$！与超过 $92\%$ 的正值 $I_t > 0$ 相乘后，便机械地把 $79.94\%$（SW）与 $82.11\%$（TWX） 的步推进了 $(\hat{A}_t < 0, I_t > 0)$ 象限。

（$2$）为什么 Pass 4 的 $D_{\mathrm{self}}$ 在 $t=0$ 严格为 $0$，一到 $t \ge 1$ 就 $99.84\%\text{–}100\%$ 为负？

查看 src/prompts.py 第 $197\text{–}215$ 行的 build_state_opd_messages 可知，Pass 4 在构造 Teacher 输入 $s_t$ 时，不仅删去了历史思考的内容，还直接删掉了历史助手回复中的 Thought: 这一整行标签，把前 $t$ 轮全部改成了单行 Assistant: Action: ...。这给模型注入了强烈的上下文少样本格式示范：“本对话里的助手从不写思考、只输出单行动作”；随后在当前第 $t$ 步突然强插 Assistant: Thought: 并对学生生成的 $30$ 个自由叙述 token 算对数似然，Teacher 自然倾向于立刻收束换行去写 Action:，系统性压低长思考句中词汇的概率。

表 $2.3$ 与图 $2.2$ 给出了最直接的证据：在尚无历史助手回复的 $t = 0$ 轮，SW 与 TWX 的 $D_{\mathrm{self}}$ 均值分别为 $+0.0001$ 与 $+0.0012$（负值率 $55.0\%$ 与 $51.7\%$，纯属 BF16 舍入涨落）；一旦进入 $t \ge 1$ 轮，SW 的 $1{,}864$ 步中有 $1{,}861$ 步为负（$99.84\%$，均值 $-1.1604$），TWX 的 $1{,}315$ 步更是 $1{,}315$ 步全部为负（$100.00\%$，均值 $-1.6240$）。
